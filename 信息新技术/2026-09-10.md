## 一、今日知识点

### 1. Serverless：不是“没有服务器”，而是用户少管服务器

**Serverless（无服务器计算）**是一种云计算服务与应用运行模式。底层服务器仍然存在，只是服务器配置、容量管理、扩缩容等工作更多由云平台承担，开发者主要关注业务代码和事件处理。

常见理解包括：

| 概念 | 核心定位 | 典型关键词 |
|---|---|---|
| IaaS | 提供基础计算资源 | 云主机、虚拟机 |
| PaaS | 提供开发运行平台 | 运行环境、中间件 |
| Serverless/FaaS | 按事件运行函数或服务 | 事件驱动、自动伸缩、按使用计费 |

典型流程可记为：

```text
事件触发 → 平台分配运行资源 → 执行函数/业务逻辑 → 返回结果 → 平台自动管理资源
```

📌 **国网考点：** “开发者无需直接管理服务器”“事件驱动”“自动伸缩”是 Serverless 的高辨识度关键词。

⚠️ **易错提醒：** Serverless ≠ 物理上不存在服务器；也不是所有 Serverless 产品都只有函数形态。

### 2. Spark 与 Flink：都能做大数据计算，但典型侧重点不同

Hadoop MapReduce 是经典批处理模型，而现代大数据计算常见 Spark、Flink。

| 技术 | 典型定位 | 常见考试关键词 |
|---|---|---|
| MapReduce | 经典磁盘型批处理思想 | Map、Reduce、批任务 |
| Spark | 通用分布式计算引擎 | 内存计算、批处理、统一分析 |
| Flink | 分布式流处理引擎 | 流优先、低时延、持续事件处理 |

- **Spark**通过内存计算等机制提升很多迭代和交互式计算场景的效率，也支持流式处理能力。
- **Flink**以流处理为核心模型，同时可以处理有界数据。
- **批处理**面向一批相对有限的数据集中处理；**流处理**强调数据持续到达、持续处理。

📌 **国网考点：** 若题目强调“持续到达的实时事件流、低时延处理”，Flink 往往更符合典型定位。

⚠️ **易错提醒：** 不要机械理解为“Spark只能批处理、Flink只能流处理”。考试应抓住二者的典型侧重点。

### 3. MQTT 与 CoAP：物联网应用协议的两种典型思路

| 对比 | MQTT | CoAP |
|---|---|---|
| 典型通信模型 | 发布/订阅 | 类 REST 请求/响应 |
| 常见传输基础 | TCP | UDP |
| 关键角色 | 发布者、订阅者、Broker | Client、Server、Resource |
| 典型特点 | 轻量消息、主题订阅 | 面向受限设备、资源访问 |

**MQTT**常通过消息代理（Broker）实现发布者和订阅者之间的解耦。设备可以向某个主题发布消息，订阅该主题的客户端获得消息。

**CoAP**面向受限设备和受限网络，设计思想与 Web 的资源访问方式相似，常用 GET、POST 等方法访问资源。

🧠 **速记：** MQTT 看“主题 + Broker + 发布订阅”；CoAP 看“资源 + REST 风格 + UDP”。

⚠️ **易错提醒：** MQTT 和 CoAP 都属于物联网常见应用层协议，不要与 Zigbee、LoRa 等接入/通信技术混为一类。

### 4. AI 的训练与推理：一个“学参数”，一个“用模型”

机器学习系统通常可以粗分为**训练（Training）**和**推理（Inference）**两个阶段。

| 阶段 | 主要任务 | 输入/输出直觉 |
|---|---|---|
| 训练 | 利用数据调整模型参数 | 训练数据 → 模型 |
| 推理 | 用训练好的模型处理新输入 | 新数据 → 预测/生成结果 |

同时要掌握两个常见问题：

- **过拟合**：训练数据上表现很好，但对未见数据泛化较差。
- **欠拟合**：模型连训练数据中的主要规律都没有充分学到，训练和测试表现都可能较差。

常见缓解过拟合思路包括增加有效数据、正则化、合理控制模型复杂度等；考试通常只要求识别概念，不要求推导公式。

📌 **国网考点：** “模型部署后处理用户新输入”属于推理；“根据样本反复调整参数”属于训练。

### 5. Merkle Tree：用哈希树高效验证一组数据

**Merkle Tree（默克尔树）**是一种哈希树结构。叶子节点通常与底层数据的哈希相关，上层节点由其子节点的哈希组合后继续计算哈希，最终得到一个根哈希（Merkle Root）。

简化结构：

```text
          Root
         /    \
       H12    H34
      /  \    /  \
     H1  H2  H3  H4
```

其价值在于：

- 能用较少的哈希信息验证某条数据是否属于这组数据；
- 任一底层数据变化会沿路径影响上层哈希，最终可能改变根哈希；
- 区块链中常用于组织和校验区块内交易等数据。

📌 **国网考点：** Merkle Tree 的关键词是“哈希树、根哈希、数据完整性/成员验证”。

⚠️ **易错提醒：** Merkle Tree 本身不是共识机制，也不是数字签名算法；PoW、PoS、PBFT 才属于典型共识机制范畴。

### 6. IPv6：128 位地址只是最基础的识别点

IPv6 是为应对 IPv4 地址空间不足等问题设计的新一代互联网协议。

| 对比 | IPv4 | IPv6 |
|---|---|---|
| 地址长度 | 32 bit | 128 bit |
| 常见文本表示 | 点分十进制 | 十六进制、冒号分隔 |
| 广播 | 支持广播 | 不使用 IPv4 式广播，更多使用组播等机制 |
| 地址配置 | 手工/DHCP 等 | 支持无状态地址自动配置等方式 |

IPv6 还对报头设计进行了简化和调整，并具有更大的地址空间。实际网络迁移通常不是“一夜替换”，可能采用双栈、隧道、转换等过渡方式。

📌 **国网考点：** 最稳定的记忆点是 **IPv6 地址长度 128 bit**；“IPv6完全不需要任何地址配置机制”属于错误表述。

🧠 **速记：** IPv4 = 32 位；IPv6 = 128 位。

### 7. 同态加密与安全多方计算：都想“少暴露数据”，路径不同

隐私计算不是单一技术，常见概念包括安全多方计算、同态加密、联邦学习、差分隐私等。

| 技术 | 核心思想 | 典型辨识词 |
|---|---|---|
| 同态加密 HE | 可直接对密文进行特定计算，解密结果与对明文计算存在对应关系 | 密文计算 |
| 安全多方计算 MPC | 多方共同计算一个函数，尽量不暴露各自私有输入 | 多方协同、输入保密 |
| 联邦学习 FL | 数据尽量留在本地，通过模型参数/更新等协作训练 | 数据不集中、协同训练 |
| 差分隐私 DP | 通过随机化等机制降低单个样本对结果的可识别影响 | 隐私预算、统计发布 |

📌 **国网考点：** “直接在密文上计算”优先想到同态加密；“多机构联合计算但不直接交换原始私有输入”更接近安全多方计算。

⚠️ **易错提醒：** “数据不出本地”不代表绝对没有隐私风险，联邦学习仍需要配合安全机制防范信息泄露。

### 8. 工业互联网平台：连接设备、汇聚数据、支撑工业应用

**工业互联网**强调新一代信息通信技术与工业系统深度融合。工业互联网平台通常位于工业设备与上层工业应用之间，承担设备连接、数据汇聚、分析处理、模型与应用支撑等能力。

可用简化层次理解：

```text
工业设备/传感器
      ↓
网络与边缘侧
      ↓
工业互联网平台（连接、数据、模型、服务）
      ↓
生产优化、设备运维、质量分析等工业应用
```

与几个相邻概念区分：

- **工业物联网 IIoT**：更强调工业场景中的设备感知、连接和数据交互。
- **CPS 信息物理系统**：强调计算、通信与物理过程的紧密融合和闭环交互。
- **数字孪生**：强调用数字模型映射、描述并分析物理对象或过程。

📌 **国网考点：** “工业设备接入 + 数据汇聚 + 工业应用支撑”通常指向工业互联网平台；数字孪生不是工业互联网平台的同义词。

## 二、国网风格练习题

### 1. 关于 Serverless 的说法，正确的是（ ）。

A. Serverless 表示应用运行过程中不存在任何物理服务器  
B. Serverless 要求用户自行维护全部底层服务器  
C. Serverless 常强调事件驱动、自动伸缩和减少服务器管理工作  
D. Serverless 与云计算无关

**答案：C**

**解析：** Serverless 的“无服务器”是从开发者管理视角而言，底层服务器仍然存在，只是基础设施管理更多由平台承担。A 把逻辑抽象误解为物理不存在；B 与其目标相反；D 错误。

### 2. 下列最符合 Flink 典型优势场景的是（ ）。

A. 持续到达的实时事件流处理  
B. 只用于保存静态文件  
C. 只负责 Hadoop 集群资源调度  
D. 只用于关系数据库事务管理

**答案：A**

**解析：** Flink 是典型分布式流处理引擎，适合持续事件和低时延数据处理。资源调度是 YARN 等组件的典型职责，文件存储和关系事务也不是 Flink 的核心定位。

### 3. MQTT 中负责在发布者和订阅者之间转发消息的典型组件是（ ）。

A. Broker  
B. Hypervisor  
C. NameNode  
D. Merkle Root

**答案：A**

**解析：** MQTT 采用发布/订阅模式，Broker（消息代理）负责接收并按主题向订阅者分发消息。Hypervisor 管理虚拟机；NameNode 属于 HDFS；Merkle Root 是哈希树根。

### 4. 关于 CoAP 的典型描述，正确的是（ ）。

A. 它是区块链共识算法  
B. 它常面向受限设备，采用类 REST 的资源访问思想  
C. 它只能运行在大型数据中心  
D. 它是 5G 三大业务场景之一

**答案：B**

**解析：** CoAP 是面向受限环境的轻量应用层协议，常基于 UDP 并采用类似 REST 的资源访问思想。其余选项均混淆了技术类别。

### 5. 某模型利用大量样本反复调整内部参数，这一过程主要属于（ ）。

A. 推理  
B. 训练  
C. 网络切片  
D. 数据备份

**答案：B**

**解析：** 训练阶段利用数据优化模型参数；推理是使用已经训练好的模型处理新输入。C、D 与机器学习生命周期无关。

### 6. 一个模型在训练集准确率很高，但面对未见样本表现明显下降，这最符合（ ）。

A. 欠拟合  
B. 过拟合  
C. 资源池化  
D. 高可用

**答案：B**

**解析：** 过拟合的典型表现是对训练数据拟合很好但泛化能力较差。欠拟合则通常连训练数据中的规律也未充分学习。

### 7. Merkle Tree 最典型的结构特征是（ ）。

A. 使用哈希逐层构造树并形成根哈希  
B. 使用私钥对所有节点进行对称加密  
C. 本质上是一种无线接入标准  
D. 本质上是一种虚拟机监控器

**答案：A**

**解析：** Merkle Tree 是哈希树，通过逐层哈希形成 Merkle Root，可辅助数据完整性和成员验证。它不是共识算法、无线标准或 Hypervisor。

### 14. 【间隔复习】关于 SDN 与 NFV 的区别，正确的是（ ）。

A. SDN 重点是控制平面与数据平面分离，NFV 重点是用软件化方式实现网络功能  
B. SDN 与 NFV 完全相同  
C. NFV 是一种图像压缩标准  
D. SDN 是一种区块链共识机制

**答案：A**

**解析：** SDN 强调网络控制逻辑与数据转发分离和可编程控制；NFV 强调将传统专用网络设备中的功能软件化、运行在通用计算平台上。二者可结合但不是同义词。

### 15. 【间隔复习】下列关于 RFID 与二维码的说法，正确的是（ ）。

A. RFID 必须依靠摄像头识别图形  
B. 二维码主要依靠无线射频完成识别  
C. RFID 可利用射频方式非接触识别标签  
D. 二者都属于区块链技术

**答案：C**

**解析：** RFID 利用射频识别电子标签，通常不要求光学可视对准；二维码依赖摄像头或扫描器读取图形编码。A、B 正好颠倒了两者机制。
