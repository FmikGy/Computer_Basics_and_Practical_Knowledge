## 一、今日知识点

### 1. Serverless：不是“没有服务器”，而是“少管服务器”

**Serverless（无服务器计算）**强调开发者主要关注业务逻辑，由云平台承担较多服务器配置、容量管理、弹性伸缩等基础设施运维工作。

| 概念 | 核心定位 | 典型辨识词 |
|---|---|---|
| IaaS | 提供虚拟机、网络、存储等基础资源 | 用户仍管理较多 OS/运行环境 |
| PaaS | 提供应用开发与运行平台 | 平台托管运行环境 |
| Serverless | 进一步弱化服务器管理感知 | 事件触发、自动伸缩、按实际使用计量 |
| FaaS | Serverless 的常见实现形态之一 | 函数、事件触发、短时执行 |

- **Serverless ≠ 没有物理服务器**：服务器仍然存在，只是基础设施管理更多由平台承担。
- **FaaS（Function as a Service）**常以函数为部署和执行单元，可由 HTTP 请求、消息、对象上传等事件触发。
- Serverless 适合事件驱动、负载波动明显、间歇性任务等场景。
- 它并非所有工作负载的最佳方案；长时间稳定运行、对底层环境高度定制的任务可能采用其他架构更合适。

📌 **国网考点：** “开发者上传函数、事件到来自动执行、无需自行维护服务器”优先想到 FaaS/Serverless。

⚠️ **易错提醒：** Serverless 是云计算运行与交付模式，不代表应用脱离服务器运行。

### 2. NoSQL 四类常见数据模型：先认“键、文档、列、图”

NoSQL 通常指非传统关系型数据管理技术集合，常用于海量数据、高并发、灵活模式或特定数据关系场景。它并不是“完全不用查询语言”，也不等于“不支持任何一致性”。

| 类型 | 数据组织特点 | 典型适用场景 |
|---|---|---|
| 键值型 Key-Value | Key → Value | 缓存、会话、简单高速访问 |
| 文档型 Document | 以 JSON/BSON 等文档形式组织 | 内容管理、结构灵活的业务数据 |
| 列族型 Wide-column | 按列族等方式组织 | 大规模分布式数据、稀疏数据 |
| 图数据库 Graph | 节点、边及属性 | 社交关系、知识图谱、关系网络 |

- 关系数据库强调表、行、列、关系模型和结构化模式；NoSQL 往往在数据模型和扩展方式上更灵活。
- 图数据库的优势在于表达和遍历复杂关系，而不是因为它“能画图”。
- 文档型数据库中的一个文档可以包含较灵活的嵌套结构。

📌 **国网考点：** “好友关系、设备拓扑、知识实体关系”常优先联想到图数据库；“Key 查 Value”对应键值型。

🧠 **速记：** NoSQL 常见四类——**键、文、列、图**。

### 3. RAG、Agent、多模态：生成式 AI 三个高频新名词

#### RAG（Retrieval-Augmented Generation，检索增强生成）

基本思路可概括为：

`用户问题 → 检索外部知识 → 将相关内容作为上下文 → 大模型生成回答`

- RAG 的核心是把**外部检索到的知识**引入生成过程。
- 常用于企业知识库问答、需要引用最新或专有资料的场景。
- RAG 与模型微调不是一回事：RAG 主要在推理时引入外部知识；微调则通过训练过程调整模型参数。

#### Agent（智能体）

- 通常强调模型不仅“生成文本”，还可围绕目标进行规划、调用工具、获取环境反馈并继续执行任务。
- 常见关键词：**目标、规划、工具调用、执行、反馈**。

#### 多模态 AI

- 能处理或生成多种信息模态，例如文本、图像、语音、视频等。
- “多模态”描述的是信息类型和处理能力，不等于“多个模型简单拼在一起”。

| 概念 | 一句话辨识 |
|---|---|
| RAG | 先检索外部知识，再辅助生成 |
| 微调 | 用训练数据调整模型参数 |
| Agent | 围绕目标规划并调用工具执行 |
| 多模态 | 处理文本、图像、语音等多种模态 |

📌 **国网考点：** “企业资料经检索后送入大模型作为上下文”是 RAG；“模型自主调用搜索、数据库、API 完成多步骤任务”更偏 Agent。

### 4. PoW、PoS、PBFT：共识机制不要混成一类

共识机制用于让分布式参与方对账本状态或交易顺序等达成一致。不同机制的参与条件、性能和适用网络不同。

| 机制 | 核心思路 | 常见特点/场景 |
|---|---|---|
| PoW（工作量证明） | 通过计算工作量竞争记账机会 | 计算/能耗开销较大，常与开放网络联系 |
| PoS（权益证明） | 依据持有权益等机制选择/组织验证者 | 减少 PoW 式大量计算竞争 |
| PBFT（实用拜占庭容错） | 已知节点间多轮消息交互达成一致 | 常与许可网络、联盟链场景联系 |

- **PoW**不是“谁 CPU 主频最高谁一定记账”，核心是工作量证明机制。
- **PoS**不是简单的“持币最多者永远记账”，实际协议会有更复杂的验证者选择与惩罚机制；考试抓住“权益”即可。
- **PBFT**常用于节点身份相对明确、规模受控的许可环境，其特点与开放式 PoW 网络不同。

📌 **国网考点：** 看到“计算竞争”想 PoW；“权益/质押”想 PoS；“许可节点、多轮投票、拜占庭容错”想 PBFT。

⚠️ **易错提醒：** 共识机制解决的是分布式参与者如何就状态达成一致，不等同于哈希算法或数字签名。

### 5. 5G 三大典型场景：eMBB、URLLC、mMTC

这是选择题高频对应关系，关键在于“业务诉求 → 场景名称”。

| 场景 | 中文理解 | 关键词 | 典型例子 |
|---|---|---|---|
| eMBB | 增强移动宽带 | 高速率、大带宽 | 高清视频、沉浸式业务 |
| URLLC | 超可靠低时延通信 | 低时延、高可靠 | 工业控制、对时延敏感的控制业务 |
| mMTC | 海量机器类通信 | 海量连接、低功耗终端 | 大规模传感器、物联网终端 |

- 三类场景是对不同业务需求的典型概括，并非说一个实际网络只能支持其中一种。
- **网络切片**可在共享基础设施上提供差异化逻辑网络能力，从而适配不同业务需求。
- **MEC**通过计算下沉进一步帮助时延敏感业务，但 MEC 本身不是 5G 三大场景之一。

🧠 **速记：** **宽带 eMBB，低时延 URLLC，海量连接 mMTC。**

### 6. RPO、RTO、高可用：一个问“丢多少”，一个问“停多久”

容灾题中最容易混的是 RPO 与 RTO。

| 指标/概念 | 关注点 | 典型问题 |
|---|---|---|
| RPO（恢复点目标） | 可容忍的数据丢失量/时间窗口 | 最多允许丢多长时间的数据？ |
| RTO（恢复时间目标） | 故障后恢复业务所需目标时间 | 最多允许业务中断多久？ |
| 高可用 HA | 尽量减少服务不可用 | 如何让服务持续可用？ |
| 备份 Backup | 保存数据副本 | 如何在数据损坏后恢复？ |
| 容灾 DR | 面向严重故障/灾难恢复业务 | 如何在灾难后恢复系统与业务？ |

例：系统要求“故障后 30 分钟内恢复服务”，描述的是 **RTO**；要求“最多只能丢失故障前 5 分钟的数据”，描述的是 **RPO**。

- 高可用强调通过冗余、故障切换等手段减少中断。
- 备份是容灾的重要手段之一，但“有备份”不等于自动具备高可用能力。
- 容灾往往还涉及异地资源、复制、切换和恢复流程。

📌 **国网考点：** **RPO 看数据，RTO 看时间（停机恢复时间）。**

⚠️ **易错提醒：** RPO 越小，通常意味着允许的数据丢失越少；RTO 越小，意味着要求恢复越快。

### 7. RFID 与 NFC：都能“近场识别”，但范围与定位不同

| 对比项 | RFID | NFC |
|---|---|---|
| 定位 | 射频识别技术的广泛类别 | 近距离无线通信技术 |
| 距离 | 依具体频段、标签和系统而异，可从近距离到更远距离 | 强调很近距离交互 |
| 典型场景 | 仓储标签、资产管理、门禁、物流 | 手机支付、门禁、碰一碰交互 |
| 交互特点 | 常见读写器读取标签 | 支持近距离设备间交互，亦可读卡/卡模拟 |

- RFID 是更宽泛的射频识别概念，标签可分为无源、有源等类型。
- NFC 工作在近距离，强调便捷、安全感知较强的近场交互体验。
- **二维码**依赖光学成像识别，不属于 RFID。

📌 **国网考点：** “仓库批量识别电子标签”常指 RFID；“手机贴近 POS/门禁完成交互”常指 NFC。

⚠️ **易错提醒：** NFC 与 RFID 有技术关联，但不能把所有 RFID 都称为 NFC。

### 8. 云计算五个基本特征：选择题中的“定义级”知识

经典云计算口径常概括为五个基本特征：

1. **按需自助服务（On-demand self-service）**：用户可按需获取计算等资源，而无需每次人工协调服务提供方。
2. **广泛网络访问（Broad network access）**：能力通过网络提供，可由多类客户端访问。
3. **资源池化（Resource pooling）**：提供方将计算、存储等资源池化，为多个用户动态分配。
4. **快速弹性（Rapid elasticity）**：资源可根据需求快速扩展或收缩。
5. **可计量服务（Measured service）**：资源使用可监控、计量并用于管理或计费。

| 容易混的说法 | 判断 |
|---|---|
| 云计算必须是公有云 | 错，私有云、混合云等也属于部署模型 |
| 弹性就是永远增加资源 | 错，既可扩展也可收缩 |
| 资源池化就是所有用户共享同一数据 | 错，池化资源不等于数据无隔离 |
| 可计量意味着一定按小时收费 | 错，重点是使用量可监控和计量 |

🧠 **速记：** **按需、网络、池化、弹性、计量。**

## 二、国网风格练习题

### 1. 关于 Serverless 的说法，正确的是（ ）。

A. 应用完全不需要任何服务器运行  
B. 开发者通常无需直接管理大量底层服务器资源  
C. Serverless 与物理服务器相互排斥  
D. Serverless 只能用于数据库系统

**答案：B**

**解析：** Serverless 的“无服务器”是指开发者较少感知和管理底层服务器，而不是物理服务器消失。A、C 都把名称作了字面化误解；D 将适用范围错误限定为数据库。

### 2. 某系统主要以“键—值”形式保存会话信息，并要求按键快速读取。最符合该特点的 NoSQL 类型是（ ）。

A. 图数据库  
B. 文档数据库  
C. 键值数据库  
D. 关系数据库

**答案：C**

**解析：** Key-Value 数据库以键直接定位值，适合缓存、会话等场景。图数据库强调节点与边的关系；文档数据库以文档组织数据；关系数据库不是题干所问的 NoSQL 类型。

### 3. 企业知识库问答系统先从内部文档检索相关片段，再把片段连同问题交给大模型生成答案。这种模式最符合（ ）。

A. RAG  
B. RAID  
C. NFV  
D. PBFT

**答案：A**

**解析：** RAG 的核心是“检索外部知识 + 增强生成”。RAID 是磁盘阵列相关概念；NFV 是网络功能虚拟化；PBFT 是共识机制。

### 4. 下列最能体现 AI Agent 特征的是（ ）。

A. 只把一张图片压缩成 JPEG  
B. 根据目标规划步骤并调用外部工具完成任务  
C. 仅增加神经网络层数  
D. 仅把训练数据存入对象存储

**答案：B**

**解析：** Agent 强调围绕目标进行规划、工具调用、执行和反馈。A 属于图像处理，C 是模型结构描述，D 是存储方式。

### 5. 区块链共识机制中，与“通过计算工作量竞争记账机会”最相关的是（ ）。

A. PoW  
B. PoS  
C. PBFT  
D. RPO

**答案：A**

**解析：** PoW 即工作量证明；PoS 侧重权益/质押；PBFT 通过许可节点间消息交互达成拜占庭容错共识；RPO 是容灾指标。

### 6. 5G 场景中，最强调“海量终端连接”的是（ ）。

A. eMBB  
B. URLLC  
C. mMTC  
D. MEC

**答案：C**

**解析：** mMTC 面向海量机器类通信；eMBB 强调增强移动宽带；URLLC 强调超可靠低时延；MEC 是边缘计算概念，不是三大场景之一。

### 7. 某业务规定“发生故障后最多允许丢失最近 10 分钟的数据”。该要求主要对应（ ）。

A. RTO  
B. RPO  
C. PUE  
D. SLA 中的网络带宽

**答案：B**

**解析：** RPO 关注可容忍的数据丢失窗口；RTO 关注业务恢复所需时间。PUE 衡量数据中心能源效率。

### 8. 下列关于 RFID 与 NFC 的说法，正确的是（ ）。

A. 二维码属于 RFID 标签  
B. NFC 强调近距离无线交互  
C. 所有 RFID 系统都属于 NFC  
D. RFID 必须使用手机作为读写器

**答案：B**

**解析：** NFC 的典型特点是很近距离交互。二维码属于光学识别；RFID 是更宽泛的射频识别技术；RFID 读写器并不限于手机。

### 9. 下列哪一项不是经典云计算五个基本特征之一（ ）。

A. 资源池化  
B. 快速弹性  
C. 可计量服务  
D. 必须使用公有云

**答案：D**

**解析：** 云计算五个基本特征包括按需自助服务、广泛网络访问、资源池化、快速弹性和可计量服务。公有云只是部署模型之一，云计算并非必须采用公有云。

### 10. 【间隔复习】在微服务体系中，主要用于统一处理服务间流量治理、可观测性和通信安全等问题的是（ ）。

A. 服务网格  
B. 数据湖  
C. RAID  
D. RFID

**答案：A**

**解析：** 服务网格面向微服务间通信治理。数据湖用于数据存储与分析体系；RAID 属于磁盘阵列；RFID 属于射频识别。

### 11. 【间隔复习】设备遥测数据持续到达，系统要求数据到达后尽快完成异常检测。更适合采用（ ）。

A. 只在月底统一处理  
B. 流处理  
C. 只做离线归档  
D. 纸质记录

**答案：B**

**解析：** 持续到达、低延迟处理是流处理的典型特征；批处理更适合周期性处理有界数据集。

### 12. 【间隔复习】多个已知机构共同维护区块链账本，成员加入需要授权。该链更可能属于（ ）。

A. 公有链  
B. 联盟链  
C. 单机数据库  
D. 内容分发网络

**答案：B**

**解析：** 联盟链典型特征是多个已知组织共同治理且参与需要许可。公有链通常更开放；C、D 都不是区块链准入类型。

### 13. 【间隔复习】关于 SAN 与 NAS，下列说法正确的是（ ）。

A. NAS 典型地向客户端提供文件级访问  
B. SAN 只能保存文本文件  
C. NAS 一定使用磁带作为介质  
D. SAN 与存储网络无关

**答案：A**

**解析：** NAS 典型提供文件级共享访问；SAN 通常面向块级存储访问。B、C 都错误限定了介质或文件类型，D 与 SAN“存储区域网络”的定位相反。

### 14. 下列关于 RAG 与微调的辨析，正确的是（ ）。

A. RAG 必须重新训练模型全部参数  
B. 微调只是在推理时搜索文档  
C. RAG 可在推理时引入检索到的外部知识  
D. 二者都是 5G 网络切片技术

**答案：C**

**解析：** RAG 的典型流程是在推理阶段检索相关外部知识并将其提供给生成模型；微调则属于训练过程，通过数据调整模型参数。A、B 将二者颠倒，D 显然混淆领域。

| 仓储/物流电子标签 | RFID |
| 手机近距离支付/门禁 | NFC |
| 云计算五特征 | 按需、网络、池化、弹性、计量 |

### 最后 30 秒速背

- **Serverless：** 不是没有服务器，而是开发者少管服务器；FaaS 常见“函数 + 事件触发”。
- **NoSQL：** **键、文、列、图**；复杂关系优先想到图数据库。
- **生成式 AI：** RAG = 检索增强；Agent = 目标 + 规划 + 工具；多模态 = 多种信息形态。
- **共识：** PoW 看工作量，PoS 看权益，PBFT 看许可节点的拜占庭容错共识。
- **5G：** eMBB 看宽带，URLLC 看低时延高可靠，mMTC 看海量连接。
- **容灾：** RPO 问“最多丢多少数据”，RTO 问“最多停多久”。
- **RFID/NFC：** RFID 范围更宽，NFC 强调近距离交互；二维码不是 RFID。
- **云计算五特征：** **按需、网络、池化、弹性、计量**。
