## 一、今日知识点

### 1. 数据仓库、数据湖与湖仓一体：重点看“数据何时整理”

| 对比项 | 数据仓库 | 数据湖 | 湖仓一体 |
|---|---|---|---|
| 数据形态 | 以结构化、治理后的数据为主 | 可保存结构化、半结构化、非结构化原始数据 | 试图兼顾数据湖开放性与仓库治理能力 |
| 典型思路 | Schema-on-Write，写入前先按模式整理 | 常见 Schema-on-Read，使用时再解释模式 | 在湖上增强事务、治理、分析能力 |
| 典型用途 | BI、报表、稳定分析 | 海量原始数据沉淀、探索分析、AI 数据 | 统一分析平台、减少湖仓割裂 |

📌 **国网考点：** 看到“保存大量原始异构数据”优先想到**数据湖**；看到“面向主题、经过清洗整合、用于分析决策”更接近**数据仓库**。

⚠️ **易错提醒：** 数据湖不是“没有结构、随便存”。如果缺乏元数据、目录和治理，也可能退化成所谓“数据沼泽”。

### 2. NoSQL 四类常见模型：不是“没有 SQL”这么简单

NoSQL 常用于海量、分布式、灵活模式等场景，常见类型如下：

| 类型 | 核心理解 | 常见场景 |
|---|---|---|
| 键值型 | Key → Value | 缓存、会话、快速查找 |
| 文档型 | 以 JSON/BSON 等文档组织 | 内容、灵活业务数据 |
| 列族型 | 按列族组织大规模稀疏数据 | 大规模分布式数据 |
| 图数据库 | 节点 + 边 + 属性 | 社交关系、知识图谱、路径关系 |

📌 **国网考点：** 如果题目强调“复杂关系及关系遍历”，通常优先考虑**图数据库**。

⚠️ **易错提醒：** NoSQL 更准确地常被理解为“Not Only SQL”，并不意味着所有 NoSQL 系统都绝对不支持类似查询语言或结构化操作。

### 3. MQTT 与 CoAP：物联网应用层协议高频辨析

| 对比项 | MQTT | CoAP |
|---|---|---|
| 典型模式 | 发布/订阅 | 类 REST 请求/响应 |
| 典型传输基础 | TCP | UDP |
| 关键角色 | 发布者、订阅者、Broker | Client、Server、Resource |
| 适用特点 | 轻量消息、设备遥测、解耦 | 受限设备、资源访问、低开销 |

MQTT 中，设备通常不是彼此直接建立复杂业务关系，而是围绕 **Broker（消息代理）** 按 Topic（主题）发布和订阅消息。

CoAP 的设计思路与 Web 的 REST 风格相似，具有 GET、POST、PUT、DELETE 等方法概念，面向资源受限的物联网环境。

🧠 **速记：**

```text
MQTT → 发布/订阅 → Broker → TCP
CoAP → REST 风格 → UDP
```

⚠️ **易错提醒：** MQTT 与 CoAP 都可以用于物联网，但不能简单认为二者协议模型、传输层和使用方式完全相同。

### 4. RFID、NFC、二维码：都是识别技术，但交互方式不同

| 技术 | 是否需要无线射频 | 典型距离/特点 | 常见应用 |
|---|---|---|---|
| RFID | 是 | 可非接触识别，距离依频段和系统而异 | 物流、资产标签、门禁 |
| NFC | 是 | 极近距离，强调近场交互 | 手机支付、门禁、碰一碰 |
| 二维码 | 否 | 依赖光学成像读取 | 支付码、信息编码、商品追踪 |

NFC 可视为近距离无线通信技术，工作距离通常很短；RFID 则是更广泛的射频识别体系，标签可分为无源、有源等类型。

📌 **国网考点：** “无需接触、通过射频自动识别标签”通常指 RFID；“手机近距离支付/近场通信”优先想到 NFC。

### 5. 5G 三大场景与网络切片：一个物理网络服务不同业务

5G 三大典型场景昨日已经建立基本对应关系：

```text
eMBB  → 增强移动宽带 → 大带宽
URLLC → 超可靠低时延 → 工业控制等
mMTC  → 海量机器类通信 → 大规模物联网
```

今天补充 **网络切片（Network Slicing）**：

> 在共享物理基础设施之上，通过虚拟化、软件化等手段构建多个逻辑上相对独立的网络，以满足不同业务的性能和管理需求。

例如，同一运营网络可针对工业控制、普通移动宽带、大规模传感器分别提供不同逻辑网络能力。

📌 **国网考点：** 网络切片的关键词是**共享物理基础设施 + 多个逻辑网络 + 按业务定制**。

⚠️ **易错提醒：** 网络切片不是简单把无线频谱机械切成若干固定小块，也不是要求每种业务单独建设一套完整物理网络。

### 6. 云、边、端与 MEC：边缘计算解决“离数据太远”的问题

| 层次 | 位置 | 典型职责 |
|---|---|---|
| 云 | 集中式云/数据中心 | 大规模计算、长期存储、全局分析 |
| 边 | 靠近用户或数据源 | 低时延处理、局部分析、过滤聚合 |
| 端 | 传感器、终端、设备 | 数据产生、采集、即时控制 |

**MEC（Multi-access Edge Computing，多接入边缘计算）**强调在接近接入网络和用户的位置部署计算、存储等能力，是边缘计算在通信网络中的重要实现思路。

典型价值：

- 降低业务往返时延；
- 减少大量原始数据回传；
- 支持工业控制、车联网、AR/VR 等对时延敏感的业务；
- 与中心云协同完成全局分析和长期存储。

⚠️ **易错提醒：** **边缘计算 ≠ 不需要云。** 云更擅长全局与规模，边更擅长就近与实时。

### 7. 隐私计算：联邦学习、同态加密、安全多方计算不要混

“隐私计算”不是单一算法，而是一组希望实现“数据可用而原始数据尽量不可见”的技术体系。

| 技术 | 核心思想 | 选择题关键词 |
|---|---|---|
| 联邦学习 | 数据留在本地，多方协同训练模型 | 数据不集中、参数/更新协作 |
| 同态加密 | 可在密文上进行特定计算，解密后得到对应明文计算结果 | 密文计算 |
| 安全多方计算 MPC | 多方共同计算函数，尽量不泄露各自私有输入 | 多方联合计算、输入保密 |
| 差分隐私 | 通过随机化/噪声限制单个样本对结果的影响 | 加噪、隐私预算、统计隐私 |

📌 **国网考点：**

- “原始数据不出域、联合训练模型” → **联邦学习**；
- “直接对密文进行运算” → **同态加密**；
- “多参与方在不公开各自输入的前提下联合求结果” → **安全多方计算**。

⚠️ **易错提醒：** 联邦学习并不天然等于绝对隐私安全，实际系统仍可能结合安全聚合、差分隐私、密码技术等增强保护。

### 8. 数字孪生与 CPS：虚实映射 vs 信息世界与物理过程深度融合

**数字孪生（Digital Twin）**：为物理对象、设备、生产线或系统建立持续更新的数字化映射，通过数据连接实现状态监测、仿真、预测和优化。

典型链路：

```text
物理实体 → 传感采集 → 数字模型
    ↑                    ↓
    └──── 分析、预测、优化、控制 ────┘
```

**CPS（Cyber-Physical Systems，信息物理系统）**：强调计算、通信、控制与物理过程的深度融合，形成感知—计算—通信—控制闭环。

| 概念 | 更突出的关键词 |
|---|---|
| 数字孪生 | 数字映射、模型同步、仿真预测 |
| CPS | 信息系统与物理过程融合、闭环控制 |

典型应用包括智能制造、设备预测性维护、智慧能源和智能电网等。

⚠️ **易错提醒：** 数字孪生不是简单的“三维模型”。只有静态模型而没有现实数据持续映射和业务分析，通常不足以体现完整数字孪生思想。

### 9. 块存储、文件存储、对象存储：云存储题常考访问方式

| 类型 | 组织/访问方式 | 典型特点 |
|---|---|---|
| 块存储 | 将数据作为块设备提供 | 类似磁盘，适合数据库、虚拟机磁盘 |
| 文件存储 | 文件 + 目录层次 | 用户直观、共享文件场景常见 |
| 对象存储 | 对象 + 元数据 + 唯一标识 | 易扩展，适合海量非结构化数据 |

📌 **国网考点：** “虚拟机系统盘/数据库磁盘”常与块存储对应；“目录树、共享文件”对应文件存储；“海量图片、视频、备份、静态资源”常对应对象存储。

⚠️ **易错提醒：** 对象存储不是传统文件系统的目录树访问模式，也不应简单理解成“数据库中的对象”。

### 10. AI 滚动补充：分类、回归、聚类的任务边界

| 任务 | 常见学习方式 | 输出/目标 |
|---|---|---|
| 分类 | 监督学习 | 离散类别，如“正常/故障” |
| 回归 | 监督学习 | 连续数值，如负荷预测值 |
| 聚类 | 无监督学习 | 根据相似性自动分组 |

例子：

- 根据历史标注邮件判断“垃圾/正常” → **分类**；
- 预测明天某时刻用电负荷数值 → **回归**；
- 没有预先标签，把用户按行为相似性分组 → **聚类**。

⚠️ **易错提醒：** “分类”和“聚类”都可能产生若干组，但分类通常已有目标类别标签，聚类通常没有预定义标签。

## 二、国网风格练习题

### 1. 与数据仓库相比，数据湖更典型的特点是（ ）。

A. 只能存储关系型表格  
B. 更适合保存多种形态的原始数据  
C. 写入前必须全部转换成统一关系模式  
D. 只能用于实时流处理

**答案：B**

**解析：** 数据湖可以保存结构化、半结构化和非结构化等多种数据，通常强调以较原始形态沉淀数据。A、C 都把数据湖错误地限制为传统关系型仓库模式；D 也错误，数据湖不是只能用于流处理。

### 2. 某系统需要高效表示“用户—好友—共同关注”等复杂关系并进行关系遍历，较适合采用的 NoSQL 类型是（ ）。

A. 图数据库  
B. 键值数据库  
C. 纯文本文件  
D. 块存储

**答案：A**

**解析：** 图数据库以节点和边直接表达实体及其关系，适合社交网络、知识图谱和路径分析。键值型擅长按 Key 快速访问，但不是表达复杂关系的首选。

### 3. MQTT 最典型的通信模式是（ ）。

A. 发布/订阅  
B. 电路交换  
C. 令牌传递  
D. 仅点对点文件传输

**答案：A**

**解析：** MQTT 采用轻量级发布/订阅模式，Broker 按 Topic 在发布者和订阅者之间转发消息。其典型考点就是“发布/订阅 + Broker”。

### 4. 下列关于 MQTT 与 CoAP 的说法，正确的是（ ）。

A. MQTT 典型运行于 UDP，而 CoAP 必须运行于 TCP  
B. MQTT 典型采用发布/订阅，CoAP 具有类 REST 的资源访问风格  
C. 二者都是物理层无线通信标准  
D. CoAP 的核心角色是消息 Broker

**答案：B**

**解析：** MQTT 典型基于 TCP，采用发布/订阅和 Broker；CoAP 典型基于 UDP，面向受限环境并采用类 REST 的资源模型。二者属于应用层协议思路，不是物理层无线标准。

### 5. 在 5G 三大典型应用场景中，面向大量传感器和物联网终端接入的是（ ）。

A. eMBB  
B. URLLC  
C. mMTC  
D. WLAN

**答案：C**

**解析：** mMTC 强调海量机器类通信和大规模设备连接；eMBB 强调增强移动宽带；URLLC 强调超可靠低时延。

🧠 **速记：** `eMBB=带宽，URLLC=时延/可靠，mMTC=数量。`

### 6. 5G 网络切片的核心思想更接近（ ）。

A. 为每种业务重新建设一套完全独立的物理网络  
B. 在共享基础设施上形成面向不同业务需求的逻辑网络  
C. 只对 IP 地址进行分段  
D. 将移动终端的磁盘划分为多个分区

**答案：B**

**解析：** 网络切片强调在共享物理网络资源上构建多个逻辑上相对独立、可按业务定制的网络。它不是磁盘分区，也不要求每类业务都单独建设完整物理网络。

### 7. 下列最符合边缘计算价值的是（ ）。

A. 所有数据必须先上传到远端中心云才能处理  
B. 将部分处理能力部署到靠近数据源的位置以降低时延  
C. 完全取消中心云和数据中心  
D. 只用于离线备份

**答案：B**

**解析：** 边缘计算通过就近处理降低时延和回传带宽压力，并与中心云协同。C 是常见干扰项：边缘计算不是云计算的替代品。

### 9. “允许在密文上进行计算，并在解密结果中得到对应明文计算结果”的技术是（ ）。

### 10. 关于数字孪生，下列说法最恰当的是（ ）。

### 12. 某电力系统利用有标签的历史故障数据训练模型，输出“故障/正常”两种结果，该任务属于（ ）。

### 15. 【滚动复习】区块链中更常与许可型、联盟链场景联系在一起的拜占庭容错类共识机制是（ ）。

B. FTP

## 三、今日速记

```text
【数据平台】
数据仓库 → 治理后的结构化分析数据 → 常见 Schema-on-Write
数据湖   → 多类型原始数据沉淀       → 常见 Schema-on-Read
湖仓一体 → 兼顾湖的开放性 + 仓的治理/分析能力

【NoSQL】
键值 → Key/Value
文档 → JSON/BSON 类文档
列族 → 大规模稀疏/分布式数据
图   → 节点 + 边 → 复杂关系

【物联网协议】
MQTT → 发布/订阅 → Broker → TCP
CoAP → REST 风格 → UDP

【识别】
RFID → 射频标签识别
NFC  → 极近距离通信/支付
二维码 → 光学读取，不是射频通信

【5G】
eMBB  → 大带宽
URLLC → 低时延 + 高可靠
mMTC  → 海量连接
```
